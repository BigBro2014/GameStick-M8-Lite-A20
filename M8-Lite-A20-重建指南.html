M8 Lite（全志 A20）游戏棒系统重建完全指南

适用设备：M8 Lite / Game Stick 4K Lite / M8 游戏棒（全志 Allwinner A20 方案，配 2.4G 无线 HID 手柄） · 整理日期：2026-10-23

先说结论：
  1. 这类游戏棒没有内部系统存储，整个系统（引导程序 + 系统 + 游戏库）都烧在 TF 卡上。所以"SD 卡镜像损坏" = 无法启动，这是设计使然，不是卡"坏"了那么简单。
  2. 重建的本质 = 给 TF 卡烧入一张"完整系统镜像"（整卡原始写入，不是拷贝文件）。
  3. 最大难点：市面上的"M8"其实有多种主板方案（RK3032 / 海思 Hi3798 / 晶晨 aml8726 / 全志 A20……），镜像互不通用，必须找到与你板子版本一致的镜像。
  4. A20 方案的公开镜像目前很少见，如果实在找不到，可以走方案 B：自制 Linux 游戏系统（见第九节）。

一、先鉴定你的板子版本（最关键的一步）

"M8"只是个外壳商品名，内部主板至少有 4 种方案。刷错方案的镜像一定开不了机。请按以下方法确认你的机器：

1能开机的话：进入系统的设置 / 关于 / 版本信息，拍下版本号。常见格式如 SEGAM-M8-8001100 V8.0、M8 20240926 release v6.0、M8-V7.3 V1.0.0 2024-09-26。A20 绿板的丝印版本形如 M8-A20-V1.0-072423。
2拆开外壳看 PCB：主板丝印 + 主芯片丝印（A20 方案主芯片上印 Allwinner A20，绿色 PCB）。论坛找镜像时帖子里通常都要对丝印。
3看购买记录 / 包装 / 原装卡：原装 TF 卡根目录有时有版本说明文件。

二、理解系统结构（为什么卡插电脑上"读不了"）

  • 整机即"U 盘大小"的 HDMI 棒，TF 卡就是它的硬盘：引导程序、系统、游戏库全部在卡上。
  • 卡的引导程序位于"分区表"应该在的位置，所以插上电脑经常提示"需要格式化"或显示 0 字节 / 异常容量——这是设计如此，此时千万不要点格式化。
  • 因此烧录系统必须用整卡镜像写入工具（Win32DiskImager / BalenaEtcher / USB Image Tool / DiskGenius 分区还原），不能靠复制粘贴。
  • 冷知识：用数据线（注意盒内附带线很多是"仅充电"线）把棒子连电脑，会挂载出一个约 1GB 的分区用于导游戏。

三、准备工作清单

  • 一张全新的高质量 TF 卡（闪迪 / 三星 / 金士顿，Class 10 以上）。扩容卡是这个圈子第一大失败原因——先用 H2testw 测一下真实容量。
  • 容量：与原装卡相同最稳（镜像是按原卡容量制作的）。用更大容量也可以，烧录后用 DiskGenius 把游戏分区扩展到全卡（见第七节）。
  • 一个质量好的 USB 读卡器（烧录失败 often 是读卡器的锅）。
  • Windows 电脑一台。
  • 工具软件：Win32DiskImager 或 BalenaEtcher（整卡烧录）、DiskGenius（分区备份/还原/扩容）、H2testw（测卡）、SD Card Formatter（格式化）。
  • 如果原卡还能被读取，先整卡备份：Win32DiskImager → 选盘符 → 点 Read → 保存为 backup.img。万一镜像还能修，这是后悔药。

五、烧录操作（三种方法，按镜像格式选）

方法 A：整卡镜像（.img / .iso / .xdi）→ Win32DiskImager 或 BalenaEtcher

1插入新 TF 卡（通过读卡器），打开 Win32DiskImager，以管理员身份运行。
2Device 栏选中 SD 卡——务必核对容量，选错盘等于毁掉其他磁盘。
3选择镜像文件 → 点 Write → 确认。等进度到 100% 并提示完成。
4安全弹出，插回游戏棒，上电。首次开机可能等 1~3 分钟。

方法 B：分区镜像（.pmfx / .pmf）→ DiskGenius 分区还原

RK3032 的 EmuELEC 类自制系统常用这种方式：DiskGenius 左侧选中新卡 → 右键"从镜像文件还原分区" → 选 .pmfx 文件 → 等待完成。A20 方案的原厂镜像一般是整卡 .img，用方法 A 即可。

方法 C：全志卡量产（.img 卡刷包）→ PhoenixCard

如果你拿到的是全志传统卡刷包（内含 boot0/uboot/boot/system/recovery 分区）：用 PhoenixCard 工具，TF 卡格式化为 FAT32，"烧写模式"选卡量产，烧录后插设备上电，设备自动把系统写入内部存储，完成后必须拔卡再重启。仅当你的 A20 机器是"系统在内部 NAND、卡只放游戏"的结构时才用这条路；若整机系统就在卡上（你描述的情况），请用方法 A。

烧录铁律：
  • 烧录前二次确认盘符容量；电脑提示"格式化"时一律拒绝。
  • 烧录中途绝不拔卡/断电；写完后先安全弹出。
  • 刷之前先做第六节的手柄配置备份。

六、手柄配置备份与恢复（最容易踩的坑）

已知在 RK3032 方案的 M8 上，无线手柄的配置信息存放在 TF 卡的 boot 分区里。直接刷整卡镜像会把它冲掉，结果系统起来了但手柄没反应。A20 方案逻辑类似，建议同样处理：

1刷之前：DiskGenius 选中原卡 → 找到第 2 个分区（通常名为 boot）→ 右键"备份分区到镜像文件" → 保存为 boot.pmf，妥善保管。
2刷之后：DiskGenius 选中新卡 → 右键 boot 分区 →"从镜像文件还原分区" → 选刚备份的 boot.pmf → 完成。
3如果原卡已损坏无法备份：大部分 2.4G 手柄插上接收器即自动配对；不行就按住手柄上的配对键（多在电源键旁小孔或组合键）重新对码。

七、首次启动、验证与加游戏

  • 插卡 → 上电 → 等待。进系统后先到版本信息核对与你烧入的镜像版本一致。
  • 测手柄：进任意游戏，按键有无反应。
  • 加游戏：把 ROM 放到 CARD:/_data/download/<平台目录>，目录名如 nes、snes、gb、gbc、gba、md、32x、arcade、psx。然后进 User 菜单按 R2 选 Yes 刷新，新游戏即出现在列表。
  • 扩展游戏分区（用比原卡大的新卡时）：DiskGenius 找到卡上最大的 exFAT 分区（卷标通常 GameStick）→ 右键"调整分区大小"扩展到全部剩余空间。注意：有些分区工具会破坏镜像里的特殊引导信息导致无法启动，优先用 DiskGenius 或 Minitool Partition Wizard；如果扩容后开不了机，就改用同容量新卡重烧。

九、方案 B：自制 Linux 游戏系统 已完成

原厂 A20 镜像在公开渠道确实找不到（已多渠道核实）。方案 B 已从设想落地为可直接烧录的成品镜像，全部构建与校验均在本机完成：

成品镜像：D:\Projects\COM++\m8-build\build\m8-lite-a20.img（8GB 稀疏镜像）
校验状态：MBR / SPL / FAT32 / ext2 / 符号链接 / 权限 / 60+ 项读回比对全部通过
烧录工具：Rufus 或 BalenaEtcher（Windows 直接烧，无需 WSL / 无需 Linux）

烧录步骤（Windows）

1插好 TF 读卡器，确认盘符（比如 H:），容量建议 ≥ 8GB。
2打开 Rufus（rufus.ie）或 BalenaEtcher（etcher.balenena.io）。
3选择上述 m8-lite-a20.img，选择 TF 卡盘符，开始烧录。
Rufus 若弹出"检测到 DD 镜像/ISO 镜像模式"提示，选 DD 模式；Etcher 无需选择。
4烧录完成后安全弹出，插回游戏棒，上电。
烧录会整卡覆盖。如果原卡里还有想保留的东西（尤其 boot 分区里的手柄配对文件），先用 DiskGenius 整卡备份 boot.pmf 再烧——详见第六节。

首次启动预期

  1. 上电后 HDMI 约 1~3 秒出现内核启动日志（白色小字，滚动很快属正常）。
  2. 日志滚完后自动进入 RetroArch 菜单（蓝色 RGUI 界面），首次约 20~40 秒。
  3. 菜单里用方向键移动，A 确认，B 返回。
  4. 选择 Load Content → 浏览到 /mnt/games/roms/ 对应机种目录 → 选 ROM → 自动加载对应核心。
  5. 游戏内呼出菜单：按住 Select + 按 X（Quick Menu）。
  6. 退出游戏：Select + Start，或 Quick Menu 里选 Close Content（退回主菜单）。
  7. QUIT & POWER OFF（完全退出并关机）：主菜单底部选 Quit RetroArch → 屏幕提示后 15 秒内按任意键可返回 RetroArch；15 秒无操作自动关机（会先卸载文件系统，安全）。在 shell 里也可以随时输入 poweroff 关机。
  8. 即时存储（Save States）：游戏内 Select + R2 存档，Select + L2 读档；Select + R / L 切换存档槽（0~9，共 10 个位置）。也可以 Select + X 呼出 Quick Menu，用菜单里的 Save State / Load State / State Slot 操作。存档写在 TF 卡 GAMES 分区 states/ 目录，41 个核心全部支持。
加游戏：拔卡插电脑，GAMES 分区（FAT32）直接可见，把 ROM 丢进 roms/ 对应目录，安全弹出后插回游戏棒即可。分区里的 README.txt 有完整说明。

可选：在 WSL 里深度验证镜像

本机构建时已做只读校验。若你想在 WSL 里再跑一轮独立验证（文件系统 fsck + QEMU 冒烟启动测试），见随附脚本 m8-build\wsl-test.sh：

1WSL 里执行：sudo apt update && sudo apt install -y qemu-system-arm dosfstools e2fsprogs util-linux
2执行：bash /mnt/d/Projects/COM++/m8-build/wsl-test.sh
3看三项结果：fsck 无 error；目录内容齐全；QEMU 日志出现 [initramfs] root found 和 [M8] starting RetroArch...（virt 机型无帧缓冲，RetroArch 会报错退出并重启，属预期）。

注意：QEMU 没有 A20 机型，冒烟测试只能验证"内核 → initramfs → 根文件系统 → 启动脚本"这条链；SPL/U-Boot/HDMI/手柄等 A20 专属部分只能在真机上验证。

已知限制与风险（如实说明）

  • U-Boot 机型：用的是 A20-OLinuXino-Lime2 的 SPL/U-Boot（A20 DRAM 初始化通用）。万一你的板子内存类型/容量特殊导致 U-Boot 起不来，可换 deb 里其他 A20 变体重刷 8KB 处的引导（我可以帮你做）。
  • 设备树：基于 sun7i-a20-mk808c（电视盒子，与游戏棒形态最接近）打了补丁（USB 强制 host 模式、启用板载模拟声卡）。若 HDMI 没画面/手柄没反应，多半是 DTB 外设差异，换一块板子的 DTB 往往能解决。
  • HDMI 音频：主线 Linux 内核不支持 A20 的 HDMI 音频输出（补丁系列自 2020 年停更）。声音走板载模拟音频口（3.5mm，如有）或外接 USB 声卡。
  • WiFi：若板载 WiFi 模组，需要对应固件（firmware-realtek 已含常见型号；其他厂商需另找固件）。
  • 性能：A20 双核 A7 + Mali-400MP2，FC/SFC/GB/GBA/MD/街机流畅；PS1 基本可玩；N64/PSP 不现实。
  • 手柄配对文件：自制系统不继承原厂 boot.pmf，若原手柄是私有 2.4G 协议（非标准 USB HID），可能需要保留原 boot 分区（见第六节备份/恢复流程）。

十、下一步

  1. 先备份原卡（可选但推荐）：把原 TF 卡插电脑，用 DiskGenius 整卡备份，重点保留 boot 分区的手柄配对文件（第六节有流程）。
  2. 烧录：按第九节用 Rufus/Etcher 把 m8-lite-a20.img 写入 ≥8GB 的 TF 卡。
  3. 上电观察：HDMI 是否出现内核日志 → 是否进 RetroArch 菜单。把看到的现象（或拍照）告诉我。
  4. 加游戏测试：丢一个 FC ROM 进 GAMES\roms\nes\，回游戏棒 Load Content 试玩。
  5. 有问题反馈：卡在哪个阶段、HDMI 显示什么、手柄反应如何——按第八节排错表先自查，再把细节给我，我出针对性补丁（换 DTB / 调 boot.scr / 换 U-Boot 变体都可以快速重新构建）。
重新构建很容易：整套构建管线在 D:\Projects\COM++\m8-build\（Python 脚本 + 已下载的组件）。要调整任何部分——换板型 DTB、加减模拟器核心、改分区大小——告诉我，几分钟就能出新镜像。

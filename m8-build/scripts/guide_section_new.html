原厂 A20 镜像在公开渠道确实找不到（已多渠道核实）。方案 B 已从设想落地为可直接烧录的成品镜像，全部构建与校验均在本机完成：

成品镜像：D:\Projects\COM++\m8-build\build\m8-lite-a20.img（8GB 稀疏镜像）
校验状态：MBR / SPL / FAT32 / ext2 / 符号链接 / 权限 / 60+ 项读回比对全部通过
烧录工具：Rufus 或 BalenaEtcher（Windows 直接烧，无需 WSL / 无需 Linux）

  • 显示：sun4i-drm KMS + fbdev 仿真 → HDMI 输出；RetroArch 用 SDL2 fbdev + RGUI 菜单（无需 GPU 加速、无需 X11）。

烧录步骤（Windows）

1插好 TF 读卡器，确认盘符（比如 H:），容量建议 ≥ 8GB。
2打开 Rufus（rufus.ie）或 BalenaEtcher（etcher.balenena.io）。
3选择上述 m8-lite-a20.img，选择 TF 卡盘符，开始烧录。
Rufus 若弹出"检测到 DD 镜像/ISO 镜像模式"提示，选 DD 模式；Etcher 无需选择。
4烧录完成后安全弹出，插回游戏棒，上电。
烧录会整卡覆盖。如果原卡里还有想保留的东西（尤其 boot 分区里的手柄配对文件），先用 DiskGenius 整卡备份 boot.pmf 再烧——详见第六节。

首次启动预期

  1. 上电后 HDMI 约 1~3 秒出现内核启动日志（白色小字，滚动很快属正常）。
  2. 日志滚完后自动进入 RetroArch 菜单（蓝色 RGUI 界面），首次约 20~40 秒。
  3. 菜单里用方向键移动，A 确认，B 返回。
  4. 选择 Load Content → 浏览到 /mnt/games/roms/ 对应机种目录 → 选 ROM → 自动加载对应核心。
  5. 游戏内呼出菜单：按住 Select + 按 X。
  6. 退出游戏：Select + Start（Quick Menu 里选 Quit）。关机：退到命令行后输入 poweroff，或直接断电（ext2 journals 容错，但仍建议优雅关机）。
加游戏：拔卡插电脑，GAMES 分区（FAT32）直接可见，把 ROM 丢进 roms/ 对应目录，安全弹出后插回游戏棒即可。分区里的 README.txt 有完整说明。

已知限制与风险（如实说明）

  • U-Boot 机型：用的是 A20-OLinuXino-Lime2 的 SPL/U-Boot（A20 DRAM 初始化通用）。万一你的板子内存类型/容量特殊导致 U-Boot 起不来，可换 deb 里其他 A20 变体重刷 8KB 处的引导（我可以帮你做）。
  • 设备树：基于 sun7i-a20-mk808c（电视盒子，与游戏棒形态最接近）打了补丁（USB 强制 host 模式、启用板载模拟声卡）。若 HDMI 没画面/手柄没反应，多半是 DTB 外设差异，换一块板子的 DTB 往往能解决。
  • HDMI 音频：主线 Linux 内核不支持 A20 的 HDMI 音频输出（补丁系列自 2020 年停更）。声音走板载模拟音频口（3.5mm，如有）或外接 USB 声卡。
  • WiFi：若板载 WiFi 模组，需要对应固件（firmware-realtek 已含常见型号；其他厂商需另找固件）。
  • 性能：A20 双核 A7 + Mali-400MP2，FC/SFC/GB/GBA/MD/街机流畅；PS1 基本可玩；N64/PSP 不现实。
  • 手柄配对文件：自制系统不继承原厂 boot.pmf，若原手柄是私有 2.4G 协议（非标准 USB HID），可能需要保留原 boot 分区（见第六节备份/恢复流程）。
